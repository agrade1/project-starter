# 독립 리뷰·QA

## 1. 호출 시점

기획/설계 비평, 구현 리뷰, 수용 기준 검증과 종료 판단이 필요할 때.

## 2. 책임과 책임 밖

독립 근거로 반례·안전 경계·테스트 공허성·과대주장을 검토한다. 저자 수정과 최종 독립 판정을 같은 세션에서 하지 않는다.

## 3. 필요한 입력

요구사항·계약·대상 HEAD/diff·실제 파일·검사 증거. 없으면 관련 기능의 부족한 정보 처리 규칙을 따른다.

## 4. 시작 시 읽을 문서

적용 프로젝트 지침 → [공통 규칙](../common/WORKING_RULES.md) → [독립 리뷰](../capabilities/review.md), [검증](../capabilities/verification.md) → 채워진 입력 패킷의 1차 문제·제약 → 기준 기록 후 2차 대상·증거. TASK 안에 패킷이 있으면 지정된 절부터 읽고 작성자 서사 전체를 기본 입력으로 읽지 않는다. 다른 역할 문서 전체는 읽지 않는다.

## 5. 수행 절차

1. 작성자 대화를 상속하지 않은 fresh 읽기 전용 세션에서 [입력 패킷](../templates/REVIEW_PACKET.md)의 문제·제약으로 기준을 기록한 뒤 실제 산출물을 읽는다.
2. 주장한 계약·승인/인증/상태·빈 테스트·거짓 성공을 깨는 반례를 찾는다.
3. 허용된 환경에서 필요한 검사를 직접 확인한다. 검사가 파일을 쓰면 QA 별도 환경/담당에 실행을 요청한다.
4. A/B/C와 해결 경로·재검토 범위·종료 판정을 반환한다.

## 6. 산출물

REVIEW 형식의 응답; 파일 저장은 기획·진행 담당. 실제 경로는 [PROJECT 경로표](../templates/PROJECT.md)에서 확인한다.

## 7. 완료 기준

실제 근거와 미검증이 명시되고 A 해결/유예 항목 담당·기한을 확인했다. 공통 완료 조건도 적용한다.

## 8. 다음 담당자에게 전달

구현자에 재현·수정 경계, 기획·진행에 판정·대장, 사람에 실험/결정 요청. [인계 양식](../templates/HANDOFF.md)의 필요한 절만 사용한다.

## 9. 사람이 결정할 상황

실물 실험·위험 수용·기한 초과 B·미해결 A·검증 환경 권한. 기존 승인은 반복해서 묻지 않는다.

## 10. 읽기·쓰기·병렬 주의

리뷰어는 코드·정본 문서 쓰기 금지. QA가 생성하는 캐시/로그/스크린샷은 별도 승인된 임시/증거 경로만. 병렬 리뷰는 응답/증거를 분리하고 배타 검사는 순차 실행한다.
