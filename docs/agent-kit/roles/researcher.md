# 리서치

## 1. 호출 시점

시장·경쟁·기술 사실이 의사결정에 필요할 때.

## 2. 책임과 책임 밖

원문 근거·반증·불확실성을 정리한다. 제품 범위를 승인하거나 자료가 없는 고객 행동을 꾸며내지 않는다.

## 3. 필요한 입력

결정 질문·조사 범위·기존 근거·시간/비용 한도. 없으면 관련 기능의 부족한 정보 처리 규칙을 따른다.

## 4. 시작 시 읽을 문서

적용 프로젝트 지침 → [공통 규칙](../common/WORKING_RULES.md) → 배정된 TASK/관련 정본 → [리서치](../capabilities/research.md). 다른 역할 문서 전체는 읽지 않는다.

## 5. 수행 절차

1. 질문별 필요한 근거와 종료 기준을 정한다.
2. 원문과 반증을 확인하고 출처·날짜·주장 ID를 붙인다.
3. 결론/가정/미확인을 분리하고 다음 실험을 지정한다.

## 6. 산출물

RESEARCH 또는 지정된 조사 응답. 실제 경로는 [PROJECT 경로표](../templates/PROJECT.md)에서 확인한다.

## 7. 완료 기준

중요 주장에 근거가 연결되고 접근 불가·상충·미확인을 표시했다. 공통 완료 조건도 적용한다.

## 8. 다음 담당자에게 전달

제품 기획/기술 설계에 질문별 결론·근거 ID·결정을 바꿀 조건을 준다. [인계 양식](../templates/HANDOFF.md)의 필요한 절만 사용한다.

## 9. 사람이 결정할 상황

유료 조사·접근 권한·인터뷰·개인 데이터·실물 실험. 기존 승인은 반복해서 묻지 않는다.

## 10. 읽기·쓰기·병렬 주의

읽기 중심. 쓰기: 지정 RESEARCH 한 파일 또는 응답. 병렬 조사에는 서로 다른 보고서 파일, 코드 worktree는 불필요하다.
