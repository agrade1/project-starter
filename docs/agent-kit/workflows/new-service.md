# 새 서비스

[공통 규칙](../common/WORKING_RULES.md)과 [운영 모델](../common/OPERATING_MODEL.md)을 적용한다. 스타터 지침이나 아이디어 문서만 있는 상태는 새 서비스다. 실제 제품 코드가 있고 기존 흐름을 확장하는 요청이면 [기능 추가](feature.md)로 좁힌다.

## 아이디어와 기획서 접수

1. 사용자가 지정한 파일/URL을 원문으로 등록한다. 채팅으로만 받은 아이디어는 사용자가 제공한 요구 문구를 날짜와 함께 `docs/input/` 또는 기존 원문 위치에 보존하고 경로를 등록한다. 작성자 대화·자기평가는 섞지 않는다. 문서 쓰기 권한이 없으면 보존할 원문을 응답으로 넘기고 저장 담당을 지정한다. 위치가 없으면 기존 문서를 탐색하고 후보를 제시한다. 폴더는 필요할 때만 만들며 원문을 정리본으로 덮어쓰지 않는다.
2. 문제·대상·핵심 흐름·제약·필수/후속/제외·가정·미답 질문을 추출한다. PROJECT 또는 기존 PRD의 요구 ID마다 원문 절/페이지·버전과 연결한다. 읽지 못한 PDF/첨부/URL은 미확인으로 기록하고 변환/접근을 요청한다. 제목만으로 내용을 채우지 않는다.
3. 문서 간 충돌과 사용자 승인 범위를 대조한다. 아이디어에 있는 기능을 모두 구현 승인으로 취급하지 않는다. 이미 승인된 범위는 재질문하지 않고, 진행을 막지 않는 빈칸은 명시한 가정으로 남긴다.
4. 첫 사용자 흐름 하나와 행동 → 관측 결과의 수용 기준을 정한다. 기존 스택/자산을 먼저 찾는다. 프로젝트 경로표와 첫 TASK만 시작하고 모든 양식·역할을 생성하지 않는다.
5. 요청된 비평 또는 위험한 가정·되돌리기 비싼 설계가 있으면 구현 전에 [독립 비평](../capabilities/review.md)을 수행한다. 잘못된 전제는 기획 단계에서 수정한다. 개발 승인이 있으면 비평 결과를 반영해 그 범위의 구현·검증으로 이어가고, 문서만 승인됐으면 문서 인계에서 끝낸다.

| 단계·담당 | 입력 | 산출물 | 완료 조건 | 사람 확인 |
|---|---|---|---|---|
| 1 기획·진행 | 아이디어 원문·제약·작업 범위 | 원문 대응표·PROJECT 초안·필요 역할 | 문제·범위·종료점·자료 충돌 확인 | 조사/프로토타입/제품 개발 구분 |
| 2 리서치(필요 시) | 결정을 바꿀 질문 | RESEARCH·근거·미확인 실험 | 중요한 주장에 원문 연결 | 인터뷰·실물 검증·추가 비용 |
| 3 제품 기획 | 문제·근거·예산 | MVP/PRD·수용 기준 | 핵심 흐름·필수/제외·실험 분리 | 범위와 사업 판단·개발 승인 |
| 4 UX·UI + 기술 설계 | 확정 범위·기존 자산 | DESIGN·TECH_PLAN/API | 화면 상태와 데이터/오류 계약 일치 | 비주얼 방향·되돌리기 어려운 선택 |
| 5 기획·진행 | 확정 계약·필요한 사전 비평 | TASK·소유권·선행·상태·예산 | 공유 계약·수용 기준·실패 시 복귀 단계 확정 | 승인 범위 증가 시만 |
| 6 FE/BE(필요한 역할만) | TASK·설계·실제 코드 | 코드·focused 검사·인계 | 수용 기준의 구현 증거 | 새 의존성·운영 영향·범위 변경 |
| 7 독립 리뷰·QA | 요구사항·diff·검사 | REVIEW·사용자 흐름 증거 | A 해결·필수 검사·B/C 기록 | 실제 사용자 수용·미검증 실험 |
| 8 단일 통합 담당·기획 | 검토된 변경 | 로컬 통합·HANDOFF | 최종 상태 검사·변경 누락 없음 | 출시는 별도 사람 절차 |

디자인/기술 조사는 입력 계약이 안정적이고 보고서 소유권이 다를 때 병렬 가능하다. 코드 병렬화는 writer별 worktree와 소유 파일을 먼저 확정한다. 서비스 전체가 작으면 1~5는 한 기획 세션, 6은 한 구현 세션으로 합친다.

## 리뷰 실패와 인계

[공통 루프·상태 전이](../common/OPERATING_MODEL.md)를 따른다. 결함은 작성자로, 전제/계약 오류는 기획·설계로, 근거 부족은 조사로, 사람 입력·한도 도달은 미완료 인계로 분기한다. 수정 기본 최대 2회이며 세션을 바꿔도 회차를 잇는다. 필수 기준과 A가 해결되고 B/C 담당·기한을 기록해야 완료다.
