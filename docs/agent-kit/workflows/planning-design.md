# 기획·리서치·디자인·기술 설계만

목표 산출물까지 작성하고 종료한다. 코드 구현·새 서비스 scaffolding·실제 모델 추가 호출·출시를 자동으로 이어가지 않는다. [공통 규칙](../common/WORKING_RULES.md)과 [운영 모델](../common/OPERATING_MODEL.md)을 적용한다.

| 단계·담당 | 입력 | 산출물 | 완료 조건 | 사람 확인 |
|---|---|---|---|---|
| 1 기획·진행 또는 요청받은 전문 역할 | 요청·기존 자료·범위 | 산출물 종류·경로·종료점 | 역할/기능 하나 선택 | 목표나 범위가 불명확할 때 |
| 2 제품/리서치/UX·UI/기술 설계 중 해당 역할 | 필요한 정본·근거 | PRD/RESEARCH/DESIGN/TECH_PLAN 중 요청 결과 | 근거·가정·구현 가능한 계약·미확인 표시 | 유료 조사·비주얼/사업 방향·실물 검증 |
| 3 독립 비평(위험/요청에 따라) | 최종 초안·원문 근거 | REVIEW 응답 | A 해결·B/C 기록 | 남은 주요 선택 |
| 4 기획·진행 또는 작성자 | 최종 문서·미확정 | HANDOFF | 산출물 위치·활용법·다음 승인 경계 명시 | 구현 요청 전에는 종료 |

작은 문구·디자인 변경은 기존 문서 해당 절만 갱신한다. 독립 비평을 생략했으면 그 사실을 기록하며 독립 검증 완료로 표현하지 않는다.

## 리뷰 실패와 인계

[공통 루프·상태 전이](../common/OPERATING_MODEL.md)를 따른다. 결함은 작성자로, 전제/계약 오류는 기획·설계로, 근거 부족은 조사로, 사람 입력·한도 도달은 미완료 인계로 분기한다. 수정 기본 최대 2회이며 세션을 바꿔도 회차를 잇는다. 필수 기준과 A가 해결되고 B/C 담당·기한을 기록해야 완료다.

이 워크플로의 수정은 문서 범위다. 기존 코드 결함은 별도 bugfix TASK 후보로 인계하며 코드 수정 승인 전에는 실행하지 않는다. 산출물 완료를 막는 결함이면 미완료로 남긴다.
