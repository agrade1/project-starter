# 기획·리서치·디자인·기술 설계만

목표 산출물까지 작성하고 종료한다. 코드 구현·새 서비스 scaffolding·실제 모델 추가 호출·출시를 자동으로 이어가지 않는다. [공통 규칙](../common/WORKING_RULES.md) 적용.

| 단계·담당 | 입력 | 산출물 | 완료 조건 | 사람 확인 |
|---|---|---|---|---|
| 1 기획·진행 또는 요청받은 전문 역할 | 요청·기존 자료·범위 | 산출물 종류·경로·종료점 | 역할/기능 하나 선택 | 목표나 범위가 불명확할 때 |
| 2 제품/리서치/UX·UI/기술 설계 중 해당 역할 | 필요한 정본·근거 | PRD/RESEARCH/DESIGN/TECH_PLAN 중 요청 결과 | 근거·가정·구현 가능한 계약·미확인 표시 | 유료 조사·비주얼/사업 방향·실물 검증 |
| 3 독립 비평(위험/요청에 따라) | 최종 초안·원문 근거 | REVIEW 응답 | A 해결·B/C 기록 | 남은 주요 선택 |
| 4 기획·진행 또는 작성자 | 최종 문서·미확정 | HANDOFF | 산출물 위치·활용법·다음 승인 경계 명시 | 구현 요청 전에는 종료 |

작은 문구·디자인 변경은 기존 문서 해당 절만 갱신한다. 독립 비평을 생략했으면 그 사실을 기록하며 독립 검증 완료로 표현하지 않는다.

## 리뷰 실패와 인계

| 원인 | 다음 담당·행동 | 종료·재개 조건 |
|---|---|---|
| 기존 코드 결함 | 별도 bugfix TASK 후보로 기록·인계; 코드 수정 승인 전 이 워크플로에서는 실행하지 않음 | 이 산출물의 완료를 막는 결함이면 미완료로 인계하고 별도 승인된 수정 후 재개 |
| 근거 부족 | 리서치/기술 설계가 지정 질문만 조사 | 원문/재현 근거가 도착하면 재검토 |
| 사람 실험·결정 필요 | 기획·진행이 구체적 질문·실험·성공 기준 전달 | 실제 응답·증거가 올 때까지 해당 단계 대기 |
| 현재 범위에서 유예 가능 | B/C를 담당·기한·유예 비용과 함께 기록 | [리뷰 규칙](../capabilities/review.md)에 따라 다음 단계 진행 |

이 워크플로 안의 문서 수정은 기본 최대 2회. A가 남으면 미완료 인계하고 범위 축소·조사·사람 결정으로 전환한다. B/C만으로 반복하지 않는다. [HANDOFF](../templates/HANDOFF.md)로 사람이 다음 세션에 전달해도 된다. 자동 호출은 필요하지 않다.
