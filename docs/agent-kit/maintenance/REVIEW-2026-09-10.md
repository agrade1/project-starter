## 외부 근거와 적용 판단

아래 자료는 2026-09-10에 원문을 확인했다. 이 팩에 대한 성능 측정 결과는 아니다.

- Anthropic의 2026-03-24 글은 작성/평가 분리와 구조화된 인계를 설명하며, 대화 압축과 새 컨텍스트 재시작을 구분한다. 모델 능력에 따라 일부 장치를 제거한 사례도 있어 매 단계 리셋이나 다중 에이전트를 의무화하는 근거로 쓰지 않았다. [Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps)
- 필요한 맥락을 선택하고 상세 조사와 요약 반환을 분리하는 방식은 전체 대화를 계속 넘기는 비용을 줄이는 참고가 된다. 요약이 원문·반대 근거를 지우지 않도록 원문 위치와 버전을 남긴다. [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- 장기 작업에서 초기 환경 정리·작은 작업 단위·진행 기록을 남기는 사례를 기존 PROJECT/TASK/HANDOFF에 대응시켰다. 별도 JSON 상태 저장소는 만들지 않았다. [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- 상태·노드·조건부 전이는 그래프 실행을 설명하는 유용한 구분이다. 문서팩에서는 의존 DAG와 수정 순환을 구분한 표로 적용하며 LangGraph 자체를 설치하지 않는다. [Graph API overview](https://docs.langchain.com/oss/python/langgraph/graph-api)

**이 팩의 설계 판단:** 문제·제약으로 평가 기준을 먼저 기록한 뒤 실제 산출물을 읽게 한다. 위 연구/사례가 이 정확한 2단계 패킷의 효과를 검증한 것은 아니다. 새 세션에도 같은 모델 편향과 요약 선택 편향은 남으며, 실제 산출물을 숨긴 요약만으로 리뷰를 끝내서는 안 된다.
