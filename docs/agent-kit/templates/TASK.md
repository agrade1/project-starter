# TASK-ID · 작업 지시

- 목표·사용자 흐름 / 연결된 수용 기준:
- 상태: ready / running / review / blocked / stale / done (착수 전 입력 부족은 blocked)
- 현재 단계 / 다음 전이 조건 / 재개 조건·담당:
- 수정 회차: 0/2 (첫 제출 후 수정 묶음 수/상한; 집계는 운영 모델 참조):
- 작업 유형·승인 범위·승인 근거:
- 입력 문서의 실제 경로 / 기준 HEAD:
- 담당 역할·세션 / 통합 담당:
- worktree 절대경로·브랜치(병렬 수정 시 필수):
- 읽기 범위 / 쓰기 허용 파일 / 금지 파일:
- 선행 작업·공유 계약 버전 / 선행 완료 증거:
- 이 산출물을 소비하는 후속 TASK / 입력 변경 시 재검토 범위:
- 포함 / 제외 / 가정·부족한 입력:
- 수행 단계:
- 산출물 경로 / 검사 명령·환경·예상 결과:
- 시간 상한 / 토큰·비용 관측 방법·한도 / 동시 세션 수:
- 중단·사람 확인 조건:
- 완료 조건 / 다음 담당·인계 경로:
- 독립 비평 입력: [REVIEW_PACKET](REVIEW_PACKET.md)의 필요한 절 또는 실제 패킷 경로:

| 작업 | 선행 | 소유 파일 | worker | 상태·근거 |
|---|---|---|---|---|
| 작은 단일 작업이면 표 생략 | | | | |

상태·분기·회차는 [운영 모델](../common/OPERATING_MODEL.md)을 따른다. 그래프 도구 대신 위 선행 표를 사용한다. 상태 변경 시 `이전 → 현재 / 이유·대상 버전·증거 / 다음 행동` 한 줄을 남긴다.
