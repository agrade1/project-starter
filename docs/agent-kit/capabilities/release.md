# 배포 준비 · 운영 인계

## 목적과 사용 시점

검증된 결과를 사람이 출시 여부를 판단하고 운영할 수 있게 정리할 때 사용한다.

## 입력과 부족한 정보

- 필수: 최종 변경·검증 결과·대상 환경·운영 책임자
- 선택: 기존 배포 절차·모니터링·백업·복구 문서
- 부족하면: 운영 권한/환경/복구 방법이 없으면 출시 준비의 미완료 항목으로 남긴다.
- 공통 경계: [작업 규칙](../common/WORKING_RULES.md). 프로젝트 경로표를 따라 기존 정본을 쓴다.

## 실행 단계

1. 실제 검증 버전과 출시 후보가 같은지 확인하고 사용자 영향·설정 변경을 요약한다.
2. 필요한 설정 이름과 안전한 설정 방법을 적되 비밀 값은 넣지 않는다. 데이터 변경은 백업·복구·이행 순서·중단 조건을 적는다.
3. 배포 전/후 확인·관측 지표·장애 탐지·연락 담당·되돌림 절차를 기존 운영 문서에 연결한다.
4. A 잔여와 B의 출시 전 기한을 확인한다. 배포 실행·운영 DB·실결제·원격 쓰기는 사람의 별도 절차로 넘긴다.
5. 준비 완료와 실제 출시 완료를 분리해 보고한다.

## 산출물

[HANDOFF 양식](../templates/HANDOFF.md)의 운영 인계 절과 기존 runbook.

## 검증과 완료

다른 담당자가 검증 버전·설정·복구·연락처·출시 승인 상태를 찾을 수 있어야 한다. 실제 배포 없이 배포 성공이라고 적지 않는다.

## 실패·보류·사람 확인

복구 불가능한 변경·미해결 A·출시 전 B 기한 미충족은 사람에게 보고한다. 출시 일정을 맞추려고 테스트를 완화하지 않는다.

## 다음 단계와 인계

사람 운영 책임자에게 출시 결정 자료·실행 절차·확인/되돌림 기준을 넘기고 종료한다.

## 작은 작업에서 생략

기획/디자인만 또는 로컬 프로토타입이면 해당 없음으로 끝낸다. 운영 플랫폼을 새로 도입하지 않는다.
