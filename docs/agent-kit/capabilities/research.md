# 리서치 · 출처 관리

## 목적과 사용 시점

시장·경쟁·기술 선택에 영향을 주는 불확실성을 줄일 때 사용한다.

## 입력과 부족한 정보

- 필수: 결정할 질문·조사 범위·허용된 도구·시간/비용 한도
- 선택: 기존 근거·고객 관측·후보 기술·경쟁 목록
- 부족하면: 접근 권한이 없으면 접근 불가를 기록한다. 검색 요약만으로 원문을 읽었다고 하지 않는다. 비용이 필요한 새 도구는 사용 범위를 확인한다.
- 공통 경계: [작업 규칙](../common/WORKING_RULES.md). 프로젝트 경로표를 따라 기존 정본을 쓴다.

## 실행 단계

1. 질문별로 답이 바뀌면 달라질 결정을 적어 조사 범위를 좁힌다.
2. 공식 제품/기술 문서·원 논문·실제 가격표 등 원문부터 확인한다. 경쟁 대안에는 수작업·무료 대안도 넣는다. 실제 사용자와 구매 결정자를 구분하고, 큰 시장 규모를 진입 가능성의 증거로 대체하지 않는다. 새 사업 조사에서는 문제의 빈도·강도와 현재 행동, 가격·지불 거부 이유, 접근 가능한 첫 사용자 채널, 1인 운영 부담의 근거를 확인한다.
3. URL·제목·발행자·발행일(없으면 미상)·접근일·해당 주장의 근거를 기록한다. 변경 가능한 사실은 최신 원문을 확인한다.
4. 지지 근거와 반증을 함께 비교한다. 인용과 추론, 관측과 마케팅 주장을 구별한다. 유료 서비스나 개인정보를 자료 수집 명분으로 임의 사용하지 않는다.
5. 다음 결정에 충분하면 멈춘다. 부족하면 필요한 실험·자료·담당을 정확히 넘긴다.

## 산출물

[RESEARCH 양식](../templates/RESEARCH.md). 조사한 사실을 주장 ID로 연결하고 미확인 질문을 남긴다.

## 검증과 완료

중요 주장마다 실제 원문이 지지하는지 대조하고 접근 불가·상충 근거를 표시한다. 출처 개수 자체를 품질로 간주하지 않는다.

## 실패·보류·사람 확인

인증·네트워크·예산 부족을 구분한다. 막힌 경로를 반복 호출하지 말고 대체 근거 또는 사람의 실험으로 넘긴다.

## 다음 단계와 인계

제품 기획·기술 설계에 결정별 근거 ID, 확신 한계, 선택을 바꿀 조건을 준다.

## 작은 작업에서 생략

이미 검증된 근거가 충분하면 새 조사를 생략한다. 기술 사실 하나면 해당 공식 문서와 결론 한 단락이면 된다.
