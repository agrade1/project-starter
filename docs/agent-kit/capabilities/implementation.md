# 구현 · 원인 수정 · 로컬 통합

## 목적과 사용 시점

승인된 기능을 실제 사용자 흐름과 검증까지 완성할 때 사용한다.

## 입력과 부족한 정보

- 필수: TASK·승인 범위·수용 기준·소유 파일·실제 코드
- 선택: 디자인/기술 계약·재현 절차·기존 테스트 결과
- 부족하면: 코드와 계약을 비교한다. 목표나 수정 권한이 모호하면 먼저 읽기 조사하고 필요한 결정을 요청한다.
- 공통 경계: [작업 규칙](../common/WORKING_RULES.md). 프로젝트 경로표를 따라 기존 정본을 쓴다.

## 실행 단계

1. 기준 HEAD와 사용자 dirty 변경을 확인한다. 변경 함수의 모든 호출자와 실패 경로를 읽고 문제를 재현한다.
2. 기존 helper·표준 기능으로 가장 작은 원인 수정을 한다. FE는 사용자 상태·키보드·오류 복구, BE는 입력·권한·상태·데이터 안전을 함께 처리한다.
3. 정상 경로와 실제 위험을 잡는 focused 검사를 실행한다. 버그는 수정 전 실패/수정 후 통과하는 회귀 증거를 남긴다. 테스트 삭제·완화는 하지 않는다.
4. diff가 허용 파일·범위 안인지 확인하고 독립 리뷰에 실제 코드와 증거를 준다. A 수정 후 영향 범위를 다시 검사한다.
5. 통합 담당 한 명이 선행/소유권/기준 HEAD를 확인하고 로컬 변경을 순차 통합한다. 누락 없는 최종 파일과 필요한 통합 검사를 확인한다. 원격 쓰기·배포는 이 단계가 아니다.

## 산출물

소유 범위의 코드·관련 테스트, [HANDOFF 양식](../templates/HANDOFF.md)의 diff/검사/미완료 기록.

## 검증과 완료

수용 기준별 관측 증거와 독립 리뷰 판정을 확인한다. 단위 테스트 통과만으로 사용자 흐름이나 출시 완료를 선언하지 않는다.

## 실패·보류·사람 확인

재현 불가면 추정 수정하지 말고 필요한 자료를 남긴다. 범위 밖 파일·공유 계약 변경은 해당 담당에게 라우팅한다. 데이터 위험·승인 우회·거짓 성공은 즉시 중단/수정한다.

## 다음 단계와 인계

독립 리뷰·QA에 대상 HEAD·diff·요구사항·검사 경로를, 통합 후 기획·진행에 완료/잔여와 다음 행동을 준다.

## 작은 작업에서 생략

새 추상화·장래 확장·불필요한 테스트 체계는 생략한다. 변경에 맞는 기존 검사만 사용한다.
