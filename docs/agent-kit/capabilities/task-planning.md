# 작업 분해 · 의존성 · 담당 파일

## 목적과 사용 시점

구현 가능한 작은 작업과 안전한 인계를 만들 때 사용한다.

## 입력과 부족한 정보

- 필수: 승인 범위·수용 기준·기존 파일·공유 계약·통합 담당
- 선택: 시간·토큰 예산·사용 가능한 세션·worktree 정보
- 부족하면: 담당 파일이나 선행 조건을 모르면 먼저 조사한다. 불명확한 작업을 병렬 worker에게 넘기지 않는다.
- 공통 경계: [작업 규칙](../common/WORKING_RULES.md). 프로젝트 경로표를 따라 기존 정본을 쓴다.

## 실행 단계

1. 사용자 흐름을 끝까지 완성하는 최소 단위로 나눈다. 각 작업의 입력·산출물·검사·제외 범위를 적는다.
2. 선행 작업과 공유 계약을 정하고 순환/미완료 의존성이 없는지 확인한다. 계약 수정은 먼저 한 담당자가 마친다. 각 입력 산출물의 생산 담당·경로·버전을 선행 작업과 연결한다. 이미 존재하는 입력은 현재 파일에서 확인하고, 아직 만들지 않은 입력을 완료된 것으로 넘기지 않는다.
3. 파일별 writer를 한 명으로 정한다. 통합 담당만 공유 정본과 통합 브랜치를 수정한다.
4. 독립된 작업이고 이득이 있을 때만 병렬화한다. writer별 worktree, 별도 임시 경로/포트, 동시 세션 상한을 배정한다.
5. 시간·수정 회차·허용 비용과 중단 조건을 적는다. 반환할 HEAD/diff·실제 검사·잔여 위험을 지정한다.
6. [운영 모델](../common/OPERATING_MODEL.md)에 따라 TASK 상태·다음 전이·실패 시 복귀 단계·후속 소비 작업을 적는다. 의존 그래프는 선행 표로 충분하다. 입력 계약이 바뀌면 영향받는 후속 작업의 기존 완료 근거를 stale로 표시한다.

## 산출물

작업별 [TASK 양식](../templates/TASK.md); 작은 작업이면 한 파일만 작성한다.

## 검증과 완료

각 수용 기준이 작업과 검사에 연결되고 소유 파일이 겹치지 않는지 확인한다. 선행 완료를 산출물과 기준 버전으로 대조한다.

## 실패·보류·사람 확인

파일 중복·dirty 공유 체크아웃·계약 불일치면 직렬 작업으로 줄인다. 계획에 없는 범위/비용 확대는 사람에게 결정받는다.

## 다음 단계와 인계

구현자에게 TASK와 최소 문서 경로, 통합 담당에게 작업 순서·기준 버전·완료 증거를 넘긴다.

## 작은 작업에서 생략

단일 수정에는 DAG 문서·worktree·다중 세션을 만들지 않는다. TASK의 핵심 항목만 사용한다.
